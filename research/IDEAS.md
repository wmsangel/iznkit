## G. Контекстные do-follow ссылки на сеть — КАРТА НА УТВЕРЖДЕНИЕ (НЕ внедрять)

Задача владельца (2026-09-29): предложить 1–2 ПОСТОЯННЫЕ контекстные do-follow
ссылки из тела нашего контента на тематически близкие сайты сети — там, где это
реально помогает читателю. Google ценит именно контекст+релевантность+постоянство;
футерные/ротируемые и плотная сетка «все ко всем» обесцениваются или похожи на
link scheme. **Сначала показать карту владельцу → внедрять только после ок.**
Правила: релевантность важнее количества; ссылка в теле, естественным анкором, по
делу; ≤1–2 на материал; дополняет ротационный футер, а не заменяет; без взаимности
ради взаимности. Кросс-ссылку СТАВИТЬ ОДНУ на пару, не «туда и обратно» с той же
страницы.

Отсеяны как нерелевантные (нет мостика из наших productivity-страниц): thecryptotools,
24zdorovie, prodom-expert, bilimjol, pawdget, izngames, foundaday, dasha-motion,
calclumen (у нас свои финкалькуляторы — дублирование).

**Предлагаемые связки (по убыванию силы):**

1. **[сильнейшая] `/tools/json-to-csv` (или дата-гайд) → ocrsnip.com.**
   Анкор (естественный): «извлечь таблицу из скана/картинки» / «PDF или картинку с
   таблицей — в таблицу». Зачем читателю: json-to-csv предполагает, что данные уже
   в тексте; OCRSnip закрывает шаг ДО — распознаёт таблицу из PDF/изображения. Оба
   браузерные, privacy-first — честное продолжение сценария.

2. **hourly-rate (гайд «как задать часовую ставку» / страница инструмента) → costtrek.com.**
   Анкор: «сравнить стоимость жизни между городами». Зачем читателю: ставка зависит
   от того, где вы/клиент; при переезде или работе на клиента из другого города
   CostTrek отвечает ровно на этот вопрос. Контент↔инструмент, по делу.

**Альтернативы (если основные не подойдут):**
- `/tools/image-file-size` или `image-size-checker` → **izntools.com** (сжатие

Итог: рекомендую внедрить №1 и №2 (по одной ссылке на материал, do-follow, в теле).

Своё рекламное место на сайте: промоутим ОДНУ нашу вещь за раз — новый инструмент,

related-tools (та же категория), футер-сети (другие сайты).

Как сделать без бэкенда (вписывается в статику + deploy-economy):
- Данные: `src/lib/featured.ts` — упорядоченный список `{ title, blurb, href, badge? }`,
  двуязычный (правим только список — гибкий самопиар без изменения кода).
- Ротация по НОМЕРУ НЕДЕЛИ (ISO week): `index = isoWeek % list.length` — детерминированно.
- Чтобы менялось КАЖДУЮ неделю без деплоя (страницы — статический SSG): считать на
  КЛИЕНТЕ (useEffect по текущей дате) — слот рендерит дефолт/первый элемент, на mount
  подставляет элемент недели. Альтернатива — build-time pick (меняется на каждом деплое;
  у нас они частые — проще, но не строго по неделям). Рекомендация: клиентский date-pick.
- Место: ОДНА точка для старта — на главной под hero (макс. охват). НЕ на каждой
  tool-странице (там уже related + аффилиат-слот). Ненавязчиво, не интерстишел
  (AdSense-friendly), с меткой вроде «Новинка / Совет недели».
- Польза: поднимает новые и недооценённые страницы (внутренняя перелинковка + показы),
  управляемый цикл внимания.
- Решить при внедрении: cadence (неделя?), место (главная / хаб / тонкая плашка),
  источник списка (вручную курируем vs авто из registry «свежие/popular»).

## I. Платформа: переезд с Vercel на Cloudflare (рассмотреть) — ⛔ БЛОКЕР

Вопрос владельца (2026-10-02): можно ли уйти с Vercel на Cloudflare Pages/Workers?
Вывод: технически да, но упирается в PDF. НЕ делать реактивно/вслепую.

- **Что едет легко:** статика (SSG), OG `force-static` (61), middleware-редирект
  локалей. Адаптер — `@opennextjs/cloudflare` (Workers) или `@cloudflare/next-on-pages`.
- **⛔ ГЛАВНЫЙ БЛОКЕР — PDF:** ~15 роутов `/api/pdf/*` с `export const runtime = "nodejs"`
  на `@react-pdf/renderer` (инвойс/чек/NDA/квитанции — ЯДРО + будущая платная фича).
  Нужен Node-runtime; на CF это Workers + `nodejs_compat`, и заведётся ли там @react-pdf
  (Node-стримы, fontkit, шрифты) — НЕ гарантировано. Решается только пилотом.
- **Риск 2:** Next 16.2.12 — свежий мажор, адаптеры CF часто отстают.
- **Переделать при переезде:** деплой-пайплайн (git→Vercel → CF `deploy:pages`),
  security-заголовки `next.config` → `_headers`, env, DNS, реверификация GSC/аналитики,
  правила deploy-economy под CF.
- **Плюсы:** стоимость (CF Pages щедрый free vs Vercel Pro + usage); консолидация —
  часть сети уже на CF Pages (thecryptotools, foldout — `deploy:pages`).
- **Против спешки:** iznkit статика-тяжёлый = дешёвый на Vercel уже сейчас; бюджет
  Vercel жрут ISR-тяжёлые calc-tools/worldtime ([[vercel-team-infra]]), не мы. Ради
  экономии логичнее начинать с них или тащить iznkit только при переезде ВСЕЙ сети.
- **Гейт перед решением:** пилот на отдельной ветке — собрать через OpenNext-адаптер и
  проверить именно PDF-роут + один динамический роут. Ответ «едет / не едет» даёт тест.
